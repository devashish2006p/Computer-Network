# Data Units in Computer Networks

In computer networks, **data is transmitted in structured units** called **data units**.  
Each layer of the network model treats data differently and adds its own **control information**.  

### What is a Data Unit?

A **data unit** is a **layer-specific representation of data** that contains the original information along with headers/trailers added by that layer.  
These units ensure data is delivered **accurately, reliably, and efficiently** across the network.

---

## Types of Data Units

### 1. Segment
- **Layer:** Transport Layer  
- **Concept:** Contains application data + transport layer header  
- **Purpose:** End-to-end delivery to the correct application; port addressing; flow/error control  
- **Example:** TCP/UDP segment created when sending a browser request  

---

### 2. Packet
- **Layer:** Network Layer  
- **Concept:** Encapsulates the segment and adds **network-layer information** (IP addresses)  
- **Purpose:** Routing, logical addressing, path selection  
- **Example:** Routers forward packets based on IP addresses  

---

### 3. Frame
- **Layer:** Data Link Layer  
- **Concept:** Encapsulates the packet with **frame header & trailer** (MAC addresses + error detection)  
- **Purpose:** Node-to-node delivery, physical addressing, error checking  
- **Example:** Ethernet / Wi-Fi transmit data in frames  

---

### 4. Bits
- **Layer:** Physical Layer  
- **Concept:** The **frame is converted into electrical, optical, or radio signals**, i.e., **bits (0s and 1s)**, for transmission over the physical medium  
- **Purpose:** Transmit data over cables, fiber optics, or wireless channels  
- **Key Points:**  
  - Bits are the **raw physical representation** of data  
  - Every frame is broken down into bits before transmission  
  - Bits are received and reassembled back into frames at the receiver  
- **Example:** On an Ethernet cable, a voltage pulse represents a `1` or `0`  

---

## How Data Flows Through Layers

**Sender Side**
1. Application generates raw data  
2. Transport Layer → **Segments**  
3. Network Layer → **Packets**  
4. Data Link Layer → **Frames**  
5. Physical Layer → **Bits transmitted over medium**  

**Receiver Side**
1. Physical Layer → receives **bits**  
2. Data Link Layer → extracts **frames**  
3. Network Layer → extracts **packets**  
4. Transport Layer → extracts **segments**  
5. Application receives original data  

---

## Quick Comparison Table

| Data Unit | Layer | Content | Addressing | Scope | Changes at Each Hop |
|-----------|-------|--------|-----------|-------|-------------------|
| Segment   | Transport | Application data + transport header | Port Number | End-to-end | No |
| Packet    | Network   | Segment + network header | IP Address | Network-wide | No |
| Frame     | Data Link | Packet + frame header & trailer | MAC Address | Local network | Yes |
| Bits      | Physical | Frame converted into 0s & 1s | N/A | Physical medium | Yes |

---

## Summary

- **Segment:** Transport layer, ensures application-level delivery  
- **Packet:** Network layer, enables routing using IP addresses  
- **Frame:** Data Link layer, node-to-node delivery & error detection  
- **Bits:** Physical layer, raw signals transmitted over the medium  

> Segment → Packet → Frame → Bits represent **the same data at different layers**, each adding its own control information to ensure accurate and reliable delivery across networks.
